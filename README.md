# בני לפקוביץ – תכנון ואופטימיזציה לנקודות מכירה

אתר One-Pager (עמוד נחיתה + כרטיס ביקור דיגיטלי) בעברית, RTL מלא.
המטרה: לגרום לבעל נקודת מכירה ליצור קשר ולתאם פגישת ייעוץ.

> **שם זמני.** השם המוצג באתר הוא שם זמני עד לבחירת שם מותג רשמי.
> לא נוצר לוגו סופי — בשלב זה מוצג סימן מילולי בלבד.

## הפעלה

האתר סטטי לחלוטין — HTML, CSS ו־JavaScript ללא ספריות חיצוניות וללא שלב בנייה.
פשוט פותחים את `index.html`, או מריצים שרת מקומי:

```bash
python3 -m http.server 8000
# ואז: http://localhost:8000
```

להעלאה לאוויר: מעתיקים את כל התיקייה לכל אחסון סטטי
(Netlify, Cloudflare Pages, GitHub Pages, או שרת אחסון רגיל).

## מה עדיין חסר כדי לעלות לאוויר

### 1. פרטי קשר — קובץ `assets/js/site.config.js`

כל הפרטים במקום אחד. כל שדה שנשאר ריק מסומן אוטומטית באתר בצהוב,
והכפתור שתלוי בו מפנה לטופס יצירת הקשר במקום להישאר קישור שבור.

| שדה | מה למלא |
|---|---|
| `siteUrl` | כתובת האתר המלאה, למשל `https://www.beni-retail.co.il` |
| `phoneDisplay` | מספר הטלפון כפי שיוצג, למשל `052-000-0000` |
| `phoneDial` | אותו מספר לחיוג, למשל `+972520000000` |
| `whatsappNumber` | מספר וואטסאפ בינלאומי ללא `+`, למשל `972520000000` |
| `email` | כתובת דוא״ל |
| `serviceAreas` | אזורי הפעילות כטקסט, למשל `ירושלים, בית שמש והסביבה` |
| `serviceAreaList` | אותם אזורים כרשימה, עבור מנועי חיפוש |
| `formEndpoint` | כתובת לקבלת הטופס (ראו סעיף 4) |
| `introOfferText` | הצעת הפתיחה, למשל `שיחת אבחון 20 דקות, ללא עלות` |
| `priceRangeText` | טווח מחיר לסקירת חנות |
| `showTestimonials` | **להעביר ל־`true` רק אחרי שהוזנו המלצות אמיתיות** |
| `googleAnalyticsId` | מזהה GA4, למשל `G-XXXXXXXXXX` |
| `metaPixelId` | מזהה Meta Pixel — להשאיר ריק כל עוד אין קמפיין פעיל |
| `showAdminNotices` | **להעביר ל־`false` לפני הפרסום** — מסתיר את ההערות הצהובות |

### 2. החלפת הדומיין — שישה מקומות

הכתובת `https://example.co.il` מופיעה כברירת מחדל ויש להחליף אותה בכל אלה:

- [ ] `index.html` — `canonical`, `og:url`, `og:image`, `twitter:image`
- [ ] `sitemap.xml` — כתובת העמוד
- [ ] `robots.txt` — כתובת מפת האתר
- [ ] `assets/js/site.config.js` — השדה `siteUrl`

תגיות השיתוף חייבות להיות כתובות ישירות ב־HTML ולא להיווצר ב־JavaScript,
מפני שוואטסאפ ופייסבוק קוראים אותן בלי להריץ סקריפטים.
כל עוד הכתובת לא הוחלפה, האתר מציג התראה בולטת למנהל האתר בראש העמוד.

### 3. תוכן שצריך לקבל מבני

- [ ] **המלצות / פרויקטים** — לכל אחד: שם העסק, עיר, סוג נקודת המכירה,
      האתגר, השינויים שבוצעו, התוצאה שהלקוח זיהה, ציטוט הלקוח + שם ותפקיד.
      נערכים ישירות ב־`index.html` באזור `id="testimonials"`.
      **שניים אמיתיים עדיפים על ארבעה חלקיים.** האזור מוסתר לגמרי כברירת מחדל.
- [ ] **אישור בכתב מכל אחד מבעלי החנויות** לפרסום השם, הציטוט והתמונות.
- [ ] **שם המותג הרשמי** — להחלפת השם הזמני בכותרת, ב־Footer וב־`<title>`.
- [ ] **שם רשת המזון בירושלים** — כרגע מופיע כ״רשת מזון מובילה בירושלים״.
      אם בני מעוניין לציין את השם המפורש, יש לוודא שאין מניעה חוזית.
- [ ] **תמחור** — טווח מחיר לסקירת חנות, ומה כוללת שיחת האבחון הראשונה.

### 4. תמונות

הפירוט המלא ב־`assets/img/README.md`. בקצרה:

- [ ] תמונת אזור עליון (חנות מזון מודרנית או תכנון סידור מדפים).
- [ ] תמונה מקצועית של בני.
- [ ] תמונות "לפני / אחרי" — שתיים לכל פרויקט.
- [ ] תמונת שיתוף לרשתות (`og-image.jpg`, 1200×630).

באתר מוצגות כרגע מסגרות מסומנות במקומן. **לא נעשה שימוש בתמונות סטוק גנריות.**

### 5. חיבור הטופס

הטופס מבצע ולידציה מלאה בצד הלקוח. **כל עוד `formEndpoint` ריק, הטופס אינו
מציג הודעת הצלחה** — הוא מודיע במפורש ששליחה אינה זמינה ומפנה לוואטסאפ או
לטלפון, ושומר את מה שהוקלד. הבחירה הזו מכוונת: הודעת "תודה, הפרטים התקבלו"
כשאיש לא קיבל אותם גורמת לאובדן לידים שקט שאיש לא ידע עליו.

הטופס שולח `POST` עם `Content-Type: application/json` ומצפה לתשובה תקינה
(`2xx`). מתאים לכל שירות טפסים (Formspree, Web3Forms), ל־Webhook של CRM,
או ל־endpoint עצמאי. מבנה הנתונים:

```json
{
  "fullname": "...", "business": "...", "storetype": "...",
  "city": "...", "phone": "...", "message": "...",
  "source": "אתר תדמית — טופס יצירת קשר",
  "submittedAt": "2026-01-01T00:00:00.000Z"
}
```

**לבדוק אחרי החיבור:** לשלוח פנייה אמיתית ולוודא שהיא הגיעה ליעד. פעמיים.

### 6. פרטים טכניים לפני העלייה

- [ ] להעביר את `showAdminNotices` ל־`false`.
- [ ] להעביר את `privacy.html` לבדיקת עורך דין ולעדכן את תאריך העדכון.
- [ ] לוודא שהאתר מוגש ב־HTTPS.
- [ ] לוודא שקובץ `_headers` נקרא על ידי ספק האחסון, או להגדיר את אותן
      כותרות ידנית בשרת.

### 7. משימות שיווק שאינן קוד

- [ ] **פרופיל עסק בגוגל** — עבור יועץ מקומי זה לרוב מקור הפניות החזק ביותר,
      והוא חינם. גם המקום שבו ביקורות מצטברות.
- [ ] **איסוף ביקורות** מלקוחות מרוצים — הדרך המהירה ביותר למלא את אזור ההמלצות.

## הגנת פרטיות ומדידה

כלי המדידה (Google Analytics ו־Meta Pixel) **אינם נטענים כלל** לפני שהמבקר
אישר זאת בבאנר ההסכמה. הבאנר מוצג רק אם הוגדר מזהה מדידה כלשהו — אתר בלי
מדידה אינו מציג באנר מיותר. ההחלטה נשמרת מקומית בדפדפן, וניתן לשנות אותה
דרך הקישור "הגדרות פרטיות" בכותרת התחתונה.

הגופנים מאוחסנים בתיקיית `assets/fonts` ומוגשים מהדומיין של האתר, כדי שלא
תועבר כתובת ה־IP של המבקרים לשרת חיצוני. ארבעה קבצים, כ־80KB בסך הכול
(Heebo ו-Assistant הם גופנים משתנים — קובץ אחד מכסה את כל טווח המשקלים).
רישיון: SIL OFL 1.1, ראו `assets/fonts/OFL.txt`.

## הגנה על הטופס

שני מסננים, ללא CAPTCHA וללא פגיעה בנגישות:

1. **שדה מלכודת** מוסתר (`data-honeypot`) שרק מילוי אוטומטי של בוט ימלא.
   פנייה שבה הוא מלא נזרקת בשקט.
2. **סף זמן** — טופס שנשלח פחות מארבע שניות אחרי טעינת העמוד נדחה עם
   בקשה לנסות שוב.

## כיוון העיצוב — "תוכנית החנות כשפה"

הכיוון נקבע על ידי מועצת העיצוב (החלטה 0001). התיעוד המלא:
`.council/DIRECTION.md`, `.council/decisions/0001-plan-as-language.md`,
ופרוטוקול הדיון ב־`.council/round1.md` ו־`.council/round2.md`.

**הבעיה שזוהתה:** החלפת הכותרת לבדה הפכה את העמוד לאתר של רואה חשבון או
סוכן ביטוח. השפה החזותית הייתה מילון כללי של "אמינות B2B" ולא הגיעה מעולם
התוכן של תכנון חנויות.

**מה שהשתנה:** אוצר המילים של תכנון קמעונאי — רשת תכנון, קו מסלול מקווקו,
סימוני אזורים, מקרא וסימוני מידה — הוא כעת השפה של העמוד כולו.
**האלמנט החתימה אינו התרשים אלא שכבת הסימון שמעליו.**

### עקרונות שמחייבים כל שינוי עתידי

1. **המסך הראשון אינו ההירו** — הוא תצוגת הקישור בוואטסאפ, ואחריו ההירו
   ב־390. כל החלטה נשפטת שם קודם.
2. **כל סימון חייב להיות סימון תכנוני.** אין דקורציה שאינה אומרת משהו על החנות.
3. **המשמעות לעולם לא מאחורי JavaScript.**
4. **טקסט הוא HTML, לא SVG** — טקסט ב־SVG מתכווץ ואינו מתפרס מחדש.
5. **שפת התרשים מתארת שיטה, לא חנות אחת.**

### מה נפסל, ולמה

- **הדגמה אינטראקטיבית** (גרירת מדפים) — פסילה נגישותית: היא מעבירה משמעות
  אל מאחורי JavaScript ואינה נגישה מקלדת. לא פסילת טעם.
- **ערכת כהה גלובלית** — `--gold-500` נותן 3.08:1 על `--navy-900` ונכשל.
  אזורים כהים תחומים מותרים ומשתמשים ב־`--gold-300`.

### בסיס

נבנה לפי סקיל ה־UI/UX שבפרויקט (`.claude/skills/ui-ux-pro-max`),
בדפוס **Trust & Authority + Minimal** — נשמר כבסיס, והוחלף מעליו בשפת התכנון.

| החלטה | ערך | נימוק |
|---|---|---|

| צבע משני | זהב חם `#e5a526` | הנעה לפעולה + תחושת יוקרה נגישה |
| כפתור ראשי | זהב עם טקסט כחול כהה | ניגודיות 7.27:1 — הרבה מעל הנדרש |
| כותרות | Heebo | גופן עברי, טווח משקלים מלא |
| גוף הטקסט | Assistant | גופן עברי קריא לטקסט רץ |

עם כיוון הטקסט — תווית שתמוקם במאפיין לוגי תקפוץ לצד השני של התרשים.
| קול | גוף ראשון יחיד | יועץ יחיד שמדבר כחברה נשמע פחות אמין, לא יותר |

### נגישות

- כל צמדי הצבעים נבדקו מול תקן WCAG. טקסט רץ: 7.05:1 ומעלה. כותרות: 15.68:1.
- כל שדות הטופס עם `<label>` מקושר, שגיאות עם `role="alert"` ליד השדה.
- כל אזורי הלחיצה בגודל 44×44 פיקסלים לפחות.
- ניווט מקלדת מלא, מצבי מיקוד גלויים, קישור "דילוג לתוכן".
- `prefers-reduced-motion` מכובד — האנימציות מבוטלות לחלוטין.
- ללא אמוג׳י כאייקונים; כל האייקונים הם SVG מוטמע.
- **האתר עובד גם ללא JavaScript** — כל התוכן מוצג, רק אפקט החשיפה מושבת.
  אזור ההמלצות מוסתר כברירת מחדל ב־HTML עצמו, כך שגם ללא JavaScript
  לא מוצגים כרטיסים ריקים.

## בדיקות שבוצעו

נבדק בדפדפן Chromium אמיתי, בכל העמודים:

- ללא גלישה אופקית ברוחבים 375 / 414 / 768 / 1024 / 1440 פיקסלים.
- ללא שגיאות JavaScript וללא בקשות רשת שנכשלו.
- אין קישורים שבורים; כל עוגן מצביע לאזור קיים.
- הגופנים המקומיים נטענים בפועל (`document.fonts.check`).
- ולידציית הטופס: שליחה ריקה, טלפון שגוי, ומסלול מלא.
- טופס ללא `formEndpoint`: מציג כשל, שומר את השדות, ואינו מדווח המרה.
- מלכודת הבוטים ומלכודת הזמן חוסמות שליחה.
- באנר ההסכמה: אין בקשת רשת אחת לכלי מדידה לפני אישור; בחירה נשמרת;
  "רק ההכרחי" מונע טעינה גם אחרי רענון.
- אזור ההמלצות מוסתר ללא JavaScript ונחשף כאשר `showTestimonials` דלוק.
- תפריט מובייל: פתיחה, סגירה ב־Esc, `aria-expanded` תקין.
- קישור "דילוג לתוכן" הוא תחנת ה־Tab הראשונה.
- `prefers-reduced-motion`: אין תוכן שנשאר מוסתר.
